# Key Import Function Solution

## 1. Problem Analysis

### 1.1 Test File Path Error
- **Problem**: The test file `src/app/api/share/__tests__/import.test.ts` has an incorrect import path
- **Analysis**: The test file imports from `../route`, but the actual implementation file is at `../import/route.ts`
- **Impact**: All tests fail, making it impossible to verify functionality correctness

### 1.2 CSRF Protection Issue
- **Problem**: API calls are blocked by CSRF protection mechanism
- **Analysis**:
  - `validateCsrf` and `checkCsrfHeader` functions in `src/lib/csrf.ts` perform CSRF validation for POST requests
  - Requests are rejected when proper `origin` or `referer` headers are not provided
- **Impact**: Cannot directly test the API using tools like curl

### 1.3 Parameter Validation Logic Issue
- **Problem**: `customName` validation logic has issues
- **Analysis**:
  - Line 35 requires `customName` to be non-empty
  - However, when using an existing group, `customName` is not actually used - the existing group's name is used instead
  - This may cause users to still need to provide `customName` when using an existing group

## 2. Technical Implementation Steps

### 2.1 Fix Test File Path Error
1. **Modify test file import path**:
   - Change the import statement in `src/app/api/share/__tests__/import.test.ts` from `import { POST } from '../route';` to `import { POST } from '../import/route';`

### 2.2 Optimize CSRF Protection Mechanism
1. **Add API path to CSRF exemption list**:
   - Add `/api/share/import` path to the `CSRF_EXEMPT_PATHS` array in `src/lib/csrf.ts`

### 2.3 Adjust Parameter Validation Logic
1. **Modify `customName` validation logic**:
   - In `src/app/api/share/import/route.ts`, no longer require `customName` when `targetGroupId` is provided
   - Only require `customName` to be non-empty when `createNewGroup` is true and no `targetGroupId` is provided
