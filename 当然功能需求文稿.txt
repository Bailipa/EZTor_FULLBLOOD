# 当然功能需求文稿

## 1. 功能需求

### 1.1 前进后退按键
- **功能描述**：在'当然'功能的闪卡界面中添加前进和后退按钮，用于切换上下单词
- **位置**：闪卡界面的顶部或底部，便于用户操作
- **交互逻辑**：
  - 前进按钮：切换到下一个单词
  - 后退按钮：切换到上一个单词
  - 边界处理：当到达第一个单词时，后退按钮禁用；当到达最后一个单词时，前进按钮禁用

### 1.2 生词本操作优化
- **功能描述**：保留现有的"加入生词本"按钮，优化其交互体验
- **交互逻辑**：
  - "加入生词本"按钮：点击后将当前单词添加到生词本
  - 状态显示：根据单词是否已在生词本中，显示相应的按钮状态
- **反馈优化**：移除现有的"已添加到我的生词本"弹窗提示，改为更简洁的视觉反馈

### 1.3 不再出现功能
- **功能描述**：添加"不再出现"按钮，点击后当前单词将不再出现在'当然'功能中
- **位置**：闪卡界面的操作区域，与"再出现"按钮共用同一位置
- **交互逻辑**：当答案显示时显示此按钮，点击后，当前单词被标记为"忽略"，并自动切换到下一个单词

### 1.4 再出现功能
- **功能描述**：添加"再出现"按钮，打开一个新的界面，显示所有被"不再出现"按钮忽略过的单词
- **位置**：闪卡界面的操作区域，与"不再出现"按钮共用同一位置
- **交互逻辑**：当答案未显示时显示此按钮，点击后打开一个单词列表界面，列表中显示所有被忽略的单词，点击列表中的单词卡片，该单词将重新出现在'当然'功能中

## 2. 实现方案

### 2.1 前进后退按键
- **实现位置**：`src/components/ui/flashcard/flashcard-widget.tsx`
- **技术实现**：
  1. 在闪卡界面添加两个新的按钮组件
  2. 实现`handlePrevious`函数，用于切换到上一个单词
  3. 修改现有`handleNext`函数，使其在非答题模式下也能切换到下一个单词
  4. 添加边界检查逻辑，控制按钮的禁用状态

### 2.2 生词本操作优化
- **实现位置**：`src/components/ui/flashcard/flashcard-widget.tsx`
- **技术实现**：
  1. 移动当前"加入生词本"按钮的位置
  2. 实现单词是否在生词本中的检查逻辑
  3. 根据检查结果显示相应的按钮状态
  4. 移除现有的alert提示，改为视觉反馈（如按钮状态变化）

### 2.3 不再出现功能
- **实现位置**：`src/components/ui/flashcard/flashcard-widget.tsx`
- **技术实现**：
  1. 添加"不再出现"按钮，与"再出现"按钮共用同一位置
  2. 实现条件渲染逻辑，当答案显示时显示此按钮
  3. 实现`handleIgnoreWord`函数，调用API标记单词为忽略
  4. 标记后自动切换到下一个单词

### 2.4 再出现功能
- **实现位置**：
  1. `src/components/ui/flashcard/flashcard-widget.tsx`（添加入口按钮）
  2. 新增文件 `src/components/ui/flashcard/ignored-words.tsx`（实现忽略单词列表界面）
- **技术实现**：
  1. 添加"再出现"按钮，与"不再出现"按钮共用同一位置
  2. 实现条件渲染逻辑，当答案未显示时显示此按钮
  3. 创建新的对话框组件，显示被忽略的单词列表
  4. 实现API调用，获取被忽略的单词列表
  5. 实现单词恢复功能，点击后将单词从忽略列表中移除

## 3. 实现难度分析

### 3.1 前进后退按键
- **难度**：低
- **原因**：
  - 基于现有的单词切换逻辑，只需添加新的按钮和函数
  - 边界检查逻辑简单
  - 不需要修改API接口

### 3.2 生词本操作优化
- **难度**：低
- **原因**：
  - 保留现有的"加入生词本"按钮，只需优化其交互体验
  - 需要添加单词是否在生词本中的检查逻辑
  - 需要修改现有的UI组件
  - 可能需要新增API接口或修改现有接口

### 3.3 不再出现功能
- **难度**：中
- **原因**：
  - 需要添加新的按钮和函数
  - 需要实现单词忽略的API接口
  - 需要确保被忽略的单词不会再出现在单词列表中

### 3.4 再出现功能
- **难度**：高
- **原因**：
  - 需要创建新的组件和界面
  - 需要实现获取被忽略单词的API接口
  - 需要实现单词恢复的API接口
  - 需要处理列表的分页和交互逻辑

## 4. 可能出现的问题

### 4.1 前进后退按键
- **问题**：当单词列表为空或只有一个单词时，按钮状态处理
- **解决方案**：添加边界检查，确保按钮状态正确

### 4.2 生词本操作优化
- **问题**：单词是否在生词本中的状态同步
- **解决方案**：在获取单词列表时同时获取生词本状态，或在点击按钮时进行检查

### 4.3 不再出现功能
- **问题**：被忽略的单词可能仍然出现在其他复习来源中
- **解决方案**：确保API在所有单词获取请求中都过滤掉被忽略的单词

### 4.4 再出现功能
- **问题**：被忽略单词列表的性能问题，当列表较大时
- **解决方案**：实现分页加载，或限制单次显示的单词数量

## 6. 总结

本需求文稿详细描述了对'当然'功能的增强，包括添加前进后退按键、优化生词本操作、添加不再出现和再出现功能。实现难度从低到高不等，其中再出现功能需要创建新的组件和API接口，难度较高。

在实现过程中，需要注意边界情况的处理、状态同步的问题以及性能优化，确保功能的稳定性和用户体验的流畅性。

通过这些改进，'当然'功能将变得更加用户友好，提供更好的单词复习体验。
