# EZTor 游客首页重构 PRD

## 1. 文档信息

- 项目：EZTor
- 页面范围：未登录首页（Guest Homepage）
- 视觉方向：轻亮产品感
- 改造范围：首页完整游客态
- 文档目的：为后续文案、设计稿、前端实现提供统一产品基线

## 2. 背景与问题

当前未登录首页更像“功能堆叠页”，而不是一个能快速建立认知并促成继续使用的产品首页。首屏存在以下问题：

1. 用户第一眼看不懂产品是什么。
2. 页面重点不明确，价值主张、输入区、登录引导同时抢注意力。
3. 首页过早强调“登录后才能用更多功能”，但没有先把游客可获得的即时价值讲清楚。
4. 视觉上偏工具拼装感，缺少主流内容/教育/效率产品常见的清晰层级和可信感。
5. “查词、保存、复习”的学习闭环没有被明确表达，用户难以理解产品长期价值。

## 3. 产品目标

本次重构目标不是单纯“变好看”，而是让游客首页承担完整的转化前职责：

1. 让新用户在 3 秒内看懂产品用途。
2. 让新用户在 10 秒内知道游客模式可以先做什么。
3. 让新用户理解登录后的增量价值，而不是感到被强迫登录。
4. 建立“查词 -> 收录 -> 复习”的学习闭环认知。
5. 提升游客态的继续浏览意愿、首次查词率和登录转化率。

## 4. 目标用户

核心用户：

1. 大学英语学习者，尤其是 CET-4 / CET-6 / 考研英语人群。
2. 想快速查单词、短语、例句的学生用户。
3. 对“背单词”已有需求，但不希望一开始进入复杂学习系统的轻量用户。

次级用户：

1. 临时需要查词、翻译、例句的人。
2. 对 AI 学习工具感兴趣，但对复杂产品有天然警惕的用户。

## 5. 产品定位

EZTor 在游客首页的产品定位应明确为：

> 一个把英语查词、理解、沉淀、复习串成闭环的轻学习工作台。

首页不是强调“大而全”，而是强调：

1. 先能查。
2. 查得清楚。
3. 登录后能持续积累与复习。

## 6. 设计原则

本次首页重构遵循以下原则：

1. 先解释价值，再展示功能。
2. 先给游客可用能力，再说明登录收益。
3. 页面只保留一个主任务：开始查词。
4. 视觉上强调清晰、可信、轻量、高完成度。
5. 降低“AI 味”，减少空泛表达，避免夸张科技感。
6. 每个区块都必须服务于“理解产品 + 促成首次使用”。

## 7. 成功指标

建议作为后续观察指标：

1. 首页首屏点击“开始查词”比例提升。
2. 游客态首次输入并发起查词的转化率提升。
3. 首页到登录页的点击率提升。
4. 游客态停留时长提升。
5. 首页首屏跳出率下降。

如果短期没有埋点改动，至少需要通过人工体验判断以下结果是否成立：

1. 不看说明也能理解产品。
2. 第一屏有明确起点。
3. 登录引导不会打断首次尝试。

## 8. 页面结构重构方案

### 8.1 顶部导航

目标：建立产品可信度，并给用户低成本浏览路径。

建议结构：

1. 左侧：EZTor Logo + 简短产品名
2. 中部导航：产品功能 / 学习方式 / 常见问题
3. 右侧操作：登录 / 免费开始

要求：

1. 顶部操作不要堆过多图标按钮。
2. GitHub、主题切换、捐赠等低优先级操作移出首屏主导航，放到页尾或次级入口。
3. 游客首页顶部只保留有助于转化的动作。

### 8.2 Hero 首屏

目标：让用户立刻知道这是什么、适合谁、第一步做什么。

建议布局：

1. 左侧文案区
2. 右侧产品演示区

Hero 核心文案任务：

1. 一句话说清楚产品是什么。
2. 一句话说清楚游客现在就能做什么。
3. 一句话说清楚登录后会多什么价值。

建议信息层级：

1. 主标题：强调“英语查词、翻译、记忆”是一体化体验
2. 副标题：说明游客可直接查公共词库，登录后解锁 AI 与生词本
3. 主 CTA：开始查词
4. 次 CTA：看看怎么用
5. 辅助价值点：公共词库可直接用 / 登录后解锁 AI 翻译 / 自动沉淀到生词本

约束：

1. 首屏不出现大段免责声明式文本。
2. “AI 生成请仔细甄别”降级到次级提示，不可占据核心注意力。
3. 不要在 Hero 区堆满功能入口按钮。

### 8.3 产品演示区

目标：用户无需阅读太多文字，也能理解核心体验。

建议内容：

1. 左侧展示游客输入框，示例内容为单词与短语混合输入。
2. 右侧展示结果卡片，包括音标、词性、中文释义、例句。
3. 用弱提示表达“AI 深度翻译 / 保存到生词本”为登录后能力。

要求：

1. 演示区必须像真实产品，不要像装饰图。
2. 示例内容要贴近学生场景，如 `apple`、`inevitable`、`take for granted`。
3. 结果卡片优先突出“查得清楚”，而不是“功能很多”。

### 8.4 游客输入区

目标：承接首屏主 CTA，让用户自然开始第一次查词。

重构方向：

1. 将游客输入区提升为首页主功能模块。
2. 标题从“公共词库查询”改为更用户导向的表达，如“先查一组你正在背的词”。
3. 强化输入提示、示例和快捷操作。
4. 登录限制提示改成温和说明，不使用阻断式语气。

保留能力：

1. 多行输入
2. TXT 导入
3. 查询结果展示
4. 未收录词提示

调整重点：

1. 减少“访客模式”标签的存在感。
2. 输入区周边减少视觉噪音。
3. 查询按钮文案更口语化和明确，如“开始查词”。

### 8.5 学习闭环区

目标：告诉用户产品不是一次性查词工具，而是学习工作流。

建议作为首页第二重点内容，使用 3 步结构：

1. 查词：快速看懂单词、短语、例句
2. 收录：登录后沉淀到个人生词本
3. 复习：通过默写与复习组继续巩固

设计要求：

1. 使用 3 张卡片或 3 段流程区块。
2. 每一步只表达一个重点，不堆文案。
3. 明确“游客可从第 1 步开始，登录后延伸到第 2、3 步”。

### 8.6 游客与登录能力对比区

目标：把登录收益说清楚，但避免强推。

建议结构：

1. 左列：游客现在可直接使用
2. 右列：登录后获得完整学习能力

游客可用：

1. 公共词库查词
2. 基础释义与例句
3. 批量输入体验

登录后解锁：

1. AI 翻译任意单词/文本
2. 生词本沉淀
3. 默写复习
4. 复习分组与长期积累

要求：

1. 文案重点是“收益”，不是“限制”。
2. 不使用大面积锁图标或过强的权限拦截语气。

### 8.7 底部 CTA 区

目标：为仍在观望的用户提供明确下一步。

建议保留两个动作：

1. 立即开始查词
2. 登录后开启完整学习流程

文案方向：

1. 强调“先用起来”
2. 强调“登录不是门槛，而是后续升级”

## 9. 文案策略

### 9.1 文案原则

1. 少讲技术，多讲使用结果。
2. 少讲“AI”，多讲“学起来更顺”。
3. 少用泛泛口号，多用具体场景。
4. 面向学生写，而不是面向开发者写。

### 9.2 应避免的表达

1. 泛化的“智能”“高效”“强大”“一站式”堆砌。
2. 首屏出现大量权限、限制、提示类文本。
3. 像管理后台或开发者工具一样的命名。

### 9.3 首页建议文案方向

首页主标题建议表达其中一个方向：

1. 把查词、理解和复习放进同一个英语学习流程
2. 不只是查到释义，更是把单词真正记住
3. 从查词开始，把英语单词沉淀成你的复习系统

副标题建议表达：

1. 游客可直接使用公共词库查词，登录后解锁 AI 翻译、生词本与默写复习。
2. 先查你现在不会的词，再决定要不要把它们留下来继续学。

## 10. 交互策略

### 10.1 首屏主交互

首页唯一主交互应是：

1. 点击“开始查词”
2. 自动滚动或聚焦到输入区

### 10.2 登录引导策略

登录引导改为渐进式：

1. 用户进入页面时不强打断。
2. 用户先看懂产品并开始尝试。
3. 当用户接触 AI 翻译、生词本、默写复习时，再出现登录收益提示。

### 10.3 结果反馈策略

1. 查询成功后结果区应强化“查得很清楚”的感受。
2. 未收录词应给出友好解释，并自然引导登录解锁 AI。
3. 结果区可提供一条轻提示，告诉用户登录后可自动保存单词。

## 11. 功能与模块取舍

本次首页游客态改造中，建议降级或移出首屏的内容：

1. 弹幕复习入口
2. 小游戏入口
3. GitHub 外链
4. 捐赠按钮
5. 过强存在感的主题切换
6. 过多的提醒 Banner

原则：

1. 不删除功能，但不应参与首页首屏核心竞争。
2. 首屏只保留会帮助“理解产品”和“开始使用”的元素。

## 12. 页面模块优先级

P0：

1. 顶部导航
2. Hero 首屏
3. 游客输入区
4. 结果区体验
5. 登录收益表达

P1：

1. 学习闭环区
2. 游客/登录能力对比区
3. 底部 CTA 区

P2：

1. FAQ 简区
2. 次级说明信息
3. 次级品牌内容

## 13. 验收标准

以下条件同时满足，视为本次首页游客态改造完成：

1. 未登录用户进入首页后，第一屏可以明确看懂产品用途。
2. 第一屏存在且只存在一个最强主行动点：开始查词。
3. 登录提示不再先于产品价值表达出现。
4. 页面整体视觉更轻、更清晰、更可信，减少“AI 拼装页”感。
5. 首页可以清楚表达游客可用能力与登录后增量价值。
6. “查词 -> 收录 -> 复习”的路径被用户理解。
7. 首屏与后续区块有一致的视觉节奏与内容层级。
