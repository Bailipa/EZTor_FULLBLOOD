# EZTor 设计风格准则

这份准则根据产品讨论、界面截图和多轮验收反馈整理。它描述的是用户反复确认过的偏好，后续设计、实现和自查都应优先遵循。

## 产品判断顺序

1. **先解决学习问题，再做视觉表达。** 功能要直接帮助四六级备考、阅读理解、词汇积累、翻译和复习。好看的主题、动效和品牌感是支撑，不是主任务。
2. **让用户少做选择。** 进入页面后给出一个明确的下一步；能自动判断的内容不要让用户配置；把低频功能收进设置或次级入口。
3. **每个操作都要有结果。** 点击、滑动、收藏、查词、提交疑问、答题和切换页面都要有清楚的状态反馈，并且能恢复、撤销或继续。

## 页面布局

- **手机优先，一屏完成主任务。** 首屏应看见当前任务、主要内容和唯一主操作；避免为了找到入口反复滚动。必要的长内容在卡片内部滚动，页面本身保持可滚动。
- **紧凑但不拥挤。** 减少顶部留白、重复标题、过大的入口卡片和占据主空间的辅助说明。内容区应比侧栏或装饰区更宽。
- **主次分明。** 主任务使用最大的视觉重量；贡献、来源、设置、导入导出等低频功能使用小按钮或卡片弹窗，不与主任务争空间。
- **不要制造返回层级。** 同一大页面内的功能使用平级标签、滑动或局部弹窗切换，避免为了进入子功能新增一个带返回按钮的页面。
- **桌面端是工作台。** 侧栏保持窄而稳定，右侧内容区充分利用宽度；多栏布局中只有真正需要滚动的主栏滚动，辅助栏固定在视口内，不留下空白。
- **工作台不是信息堆叠。** “同时呈现”必须服务于一个连续任务：阅读区保留上下文，作答区保持可见，用户不需要在题目、文章和输入框之间来回寻找。主栏与辅助栏应有明确职责，而不是把所有入口平铺出来。
- **阅读与作答要并行。** 桌面端备考阅读优先采用“文章 + 当前题目/选项”的并行布局；题目区可以独立滚动或固定在视口内，阅读位置、当前题号和提交动作始终可见。移动端再退化为单栏顺序流程。
- **阅读标记是学习资料。** 标记句子、词组或单词不是临时 UI 状态，应绑定账号、支持取消、刷新后恢复，并能在阅读档案或词库中继续使用。
- **选中即给下一步。** 用户标记单词时优先提供查翻译；标记词组或句子时提供“问 AI”，并把选中的原文、所在试卷和上下文带入已有 AI 流程。动作应在局部工具条或弹窗内完成，不打断阅读位置。

## 视觉语言

- **简洁、克制、有设计感。** 减少无意义的渐变、发光、装饰性文字和重复边框；每个光效都要说明层级或状态。
- **主题要换材质，不换结构。** 暗色、金色、靛蓝、极简等主题共享信息层级、间距和交互，只改变颜色、边框、阴影和少量圆角。文字与背景必须保持对比度，线条不能因换主题而消失。
- **配色承担状态。** 主色表示当前主动作和选中状态；成功、错误、收藏、疑问等状态要有稳定且可读的语义色，不能只靠发光或颜色深浅表达。
- **品牌统一。** EZTor 品牌 logo、应用图标、浏览器 favicon、桌面端左上角和下载页应使用同一套资产；图标要有识别度、圆角和适合小尺寸显示的轮廓。

## 导航与交互

- **径向菜单是快捷入口，不是展示墙。** 项目数量变化时实时重排，入口之间保持均匀间距；卡片、闪卡和菜单按钮不能互相遮挡。拖动方向、滑动切换和点击行为要符合直觉，并给出持续的触觉/声音/视觉反馈。
- **页面内切换优先手势。** 翻译与聊天、词库、备考练习等大页面支持左右滑动切换平级内容；动效要表现方向和连续性，不能只瞬间替换内容。
- **按钮要像动作。** 主按钮尺寸适中、文案短、图标和文字对齐；箭头放在能表达动作方向的位置。收藏按钮要支持再次点击取消收藏，问号按钮要紧邻词义并有明确标题。
- **输入遵循系统习惯。** 移动端适配系统输入法和键盘避让，焦点、回车、提交、滚动和触摸区域符合常见手机操作。
- **低频入口按需展开。** 导入、导出、来源、贡献详情、提交记录等不占首屏；使用小按钮打开局部弹窗，关闭后回到原位置。

## 学习流程

- 首页围绕“今天要完成什么”组织：目标、当前句子/单词、下一步操作和进度最优先。
- 句子中的可查词或词组用轻量边框提示可点击，但不能把正文切碎成难读的按钮墙；词组按最长匹配优先，保留标点和自然空格。
- 查词后自动进入生词/错词记录；用户可以明确标记“明白”“不认识”“有疑问”，并在公共词库流程中提交释义疑问和贡献。
- 练习、整卷模拟、听力、阅读、翻译、写作和复习共享用户记录；中断后能恢复，统计结果要能解释而不是只给一个分数。
- 手机阅读与作答采用上下分区，材料与当前题目保持同时可见、各自滚动，允许调整占比；切题不移动原文。点词查义、长按扩展原生选区，标记操作在材料区底部就近呈现；键盘打开优先保留输入和必要材料，关闭后恢复。

## 性能底线

- 首屏先显示结构和主内容，弹窗表单、贡献审核、非首屏数据按需加载。
- 不在滚动、指针移动或径向菜单拖动期间做高成本计算、重复请求或强制布局；避免动画造成强制 reflow。
- 不用未经验证的 preload；图片、字体和图标按真实使用场景加载。任何改动都要检查刷新耗时、滚动流畅度、CLS 和移动端触摸响应。
- 功能完成不等于可交付：要分别记录已实现、已验证、已部署、线上已验收，并覆盖换主题、窄屏、刷新、中断和失败恢复。

## 顶部导航的职责

- 页面名称由桌面侧栏或手机径向菜单说明，顶部不重复堆放同名标题。
- 有内页面切换时，用主题强调色栏承载现有切换入口；没有切换时保留简洁的强调色留白。
- 顶栏高度必须计入内容区尺寸；手机避让安全区及悬浮入口，保留原有滚动、草稿和切换行为。

## 明确避免

- 过大的错词本、生词本、翻译入口或顶部工具栏。
- 让用户猜“点哪里”“当前在哪套试卷”“这个词能不能点”。
- 为了压缩内容而把文字缩得难读、把卡片挤到按钮重叠，或用页面级滚动掩盖卡片高度问题。
- 删除已有功能入口或改变旧 URL、接口、品牌资源的兼容行为。
- 把未经确认的视觉偏好、资源来源或模型结果当成事实；不确定时先查项目记录或明确标注假设。

## 开发前自检

1. 这个页面的主任务是什么？用户进入后第一步是否明显？
2. 手机窄屏、桌面宽屏和所有配色主题下，主内容是否完整、可读、可操作？
3. 是否能少一个按钮、少一层页面或少一段说明？
4. 长内容、弹窗、键盘、刷新、中断和失败后，滚动与恢复是否正常？
5. 本次改动是否保留已有入口、接口、URL、记录和贡献流程？
6. 是否检查了性能，且没有为了视觉效果引入高频计算或额外请求？
