# 密钥安全管理规范

## 概述

本文档定义了 EZTor 项目中敏感信息（密钥、凭证、密码等）的安全管理规范，旨在防止敏感信息泄露和未授权访问。

---

## 1. 敏感信息分类

### 1.1 必需的环境变量

| 变量名 | 用途 | 安全等级 | 存储位置 |
|--------|------|----------|----------|
| `NEXTAUTH_SECRET` | JWT Token 签名密钥 | 🔴 高危 | 环境变量 |
| `NEXTAUTH_URL` | 应用 URL | 🟡 低危 | 环境变量 |
| `DATABASE_URL` | 数据库连接字符串 | 🔴 高危 | 环境变量 |

### 1.2 可选的环境变量

| 变量名 | 用途 | 安全等级 | 存储位置 |
|--------|------|----------|----------|
| `LLM_API_KEY` | LLM API 密钥 | 🔴 高危 | 环境变量 / 数据库 |
| `LLM_API_URL` | LLM API 端点 | 🟡 低危 | 环境变量 / 数据库 |
| `LLM_MODEL` | LLM 模型名称 | 🟢 无风险 | 环境变量 / 数据库 |
| `NEXT_PUBLIC_APP_URL` | 应用公开 URL | 🟢 无风险 | 环境变量 |

## 2. 密钥生成规范

### 2.1 NEXTAUTH_SECRET

**要求：**
- 最小长度：32 个字符
- 推荐长度：64 个字符
- 必须包含：大小写字母、数字、特殊字符中的至少 3 种

**生成方法：**

```powershell
# PowerShell (Windows)
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))

# 或者使用 OpenSSL (跨平台)
openssl rand -base64 32
```

### 2.2 DATABASE_URL

**格式：**
```
# SQLite (仅开发环境)
file:./prisma/dev.db

# PostgreSQL (生产环境推荐)
postgresql://用户名:密码@主机:端口/数据库名

# MySQL
mysql://用户名:密码@主机:端口/数据库名
```

**安全要求：**
- 生产环境必须使用强密码
- 密码不得包含 URL 特殊字符或需正确编码
- 限制数据库用户权限（最小权限原则）

## 4. 密钥轮换机制

### 4.1 轮换周期

| 密钥类型 | 推荐轮换周期 | 触发条件 |
|----------|--------------|----------|
| NEXTAUTH_SECRET | 90 天 | 泄露、人员变动 |
| DATABASE_URL | 180 天 | 泄露、数据库迁移 |
| LLM_API_KEY | 90 天 | 泄露、服务商要求 |

### 4.2 轮换流程

```
┌─────────────────────────────────────────────────────────────────┐
│                      密钥轮换流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 生成新密钥                                                  │
│     └─> 使用安全的随机数生成器                                  │
│                                                                 │
│  2. 配置双密钥过渡期 (可选)                                     │
│     └─> 新旧密钥同时有效                                        │
│                                                                 │
│  3. 更新所有服务实例                                            │
│     └─> 按顺序滚动更新，避免停机                                │
│                                                                 │
│  4. 验证服务正常运行                                            │
│     └─> 运行集成测试                                            │
│                                                                 │
│  5. 撤销旧密钥                                                  │
│     └─> 确认无服务依赖后删除                                    │
│                                                                 │
│  6. 记录轮换日志                                                │
│     └─> 时间、操作人、原因                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 NEXTAUTH_SECRET 轮换注意事项

⚠️ **重要警告**: 轮换 `NEXTAUTH_SECRET` 会导致：
- 所有已登录用户的 Session 失效
- 所有 JWT Token 需要重新签发
- 验证码系统需要同步更新

**推荐做法：**
1. 在低流量时段执行
2. 提前通知用户即将登出
3. 准备好回滚方案

### 6.2 从 Git 历史中移除敏感信息

如果敏感信息被意外提交到 Git：

```bash
# 使用 BFG Repo-Cleaner (推荐)
bfg --replace-text passwords.txt my-repo.git

# 或使用 git filter-branch
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" \
  --prune-empty --tag-name-filter cat -- --all

# 强制推送 (需要权限)
git push origin --force --all
```

## 7. 开发者最佳实践

### 7.1 代码中禁止事项

```typescript
// ❌ 错误: 硬编码密钥
const apiKey = "sk-1234567890abcdef";

// ❌ 错误: 在日志中打印密钥
console.log("Using API key:", process.env.LLM_API_KEY);

// ❌ 错误: 将密钥暴露给客户端
const clientConfig = {
  apiKey: process.env.LLM_API_KEY  // 这会暴露给浏览器!
};

// ✅ 正确: 使用环境变量验证模块
import { getRequiredEnvVar } from '@/lib/envValidator';
const apiKey = getRequiredEnvVar('LLM_API_KEY');

// ✅ 正确: 敏感值脱敏后再记录
import { maskSensitiveValue } from '@/lib/envValidator';
console.log("API Key configured:", maskSensitiveValue(apiKey));
```

### 7.2 代码审查检查清单

- [ ] 无硬编码密钥或密码
- [ ] 敏感信息使用环境变量
- [ ] 日志不包含完整密钥
- [ ] API 密钥不在客户端代码中使用
- [ ] 新增的环境变量已添加到 .env.example
