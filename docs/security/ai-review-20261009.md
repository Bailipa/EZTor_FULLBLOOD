# AI 接口与反逆向审查 — 2026-10-09

范围：当前本地工作区（包含尚未部署的传输/session加固）。只读源代码审查，不调用模型、不发送攻击请求、不更改服务器。以下为代码路径证据，不是已发生入侵的证明。未审查全部接口、历史Git秘密、实际发布产物与供应链。

## 发现（按优先级）

1. **P1 用户每日额度缺少原子预占。** `src/app/api/translate-only/route.ts:170` 检查额度，186–190调用上游，193才计数。剩余1次时多个并发请求都可通过，超出30次限制；模型已产生费用但解析/保存失败时也不计数。`translateOnlyUsage.ts:36`读取与57写入分离。修复方向：数据库事务中有条件预占、请求ID唯一约束和明确结算状态；上游计费结果不明时不无条件释放。
2. **P1 模型池配额可以超用且剩余额度丢失更新。** `src/lib/llmPool.ts:227`读取剩余数，再237覆盖写回；多个调用可从同一旧值扣减，quotaUsed增加多次而quotaRemaining只减少一次。withLlmFailover依赖候选快照且成功后扣减，不能作为硬预算门禁。修复方向：调用前原子预占、成功/失败结算和流式任务生命周期计费定义。
3. **P1 公共查询限流与翻译IP封禁仍信任可伪造头。** `src/app/api/public-translate/route.ts:11` 和 `src/app/api/translate/route.ts:75`仍取XFF首项；已核对反代追加XFF并覆盖X-Real-IP，客户端可自填首项。公共查询可换值绕过IP限流并增加数据库查询/记录写入；翻译接口的IP封禁可被绕过，但账号封禁仍是独立门禁，不能据此声称可绕过账号封禁。修复方向：统一使用经过可信反代覆盖的IP提取。
4. **P2 通用限流不是原子计数。** `src/lib/rateLimit.ts:128`读取后135/152写回。Redis并发读同值后SET会漏计；内存空窗口并发初始化也可同时通过，且默认进程本地内存97不能跨实例共享。修复方向：根据部署选用原子共享存储；Redis Lua/原子计数或成熟库的原子实现，不使用NonAtomic版本。
5. **P2 撤销管理员后在线列表仍信任旧JWT。** `src/middleware.ts:182`直接返回在线列表，以token.isAdmin检查，不进入本次新增的session数据库角色回查。撤权后旧会话在过期前仍可能读取列表。修复方向：该入口使用当前角色验证，且保留在线状态数据的正确归属；不能简单移动路由导致读取另一个进程内空Map。

## 已检查的边界

- AI工具只允许固定工具名，私人分组查询带服务端userId，未在这些已读路径发现模型可任意指定其他用户身份；不代表所有工具参数已全面验证。
- 试卷分析generateExamAnalysis使用数据库事务/用户锁、paperKey记录、服务器attempts和租约，已具备并发领取保护；本轮未做动态验证。
- Network看到本人正文/session不等于HTTPS明文传输。此前已核对NextAuth JWE和cookie flags；客户端数据可见不是本次漏洞列表。
- 未在本轮限定的src搜索中发现NEXT_PUBLIC模型密钥/秘密变量；没有扫描实际客户端包或历史提交，不能保证不存在秘密泄漏。
- 密钥数据库静态存储、CSP的unsafe-inline/unsafe-eval、全站CSRF与所有LLM入口覆盖需要后续专门审查，未在这里给出已验证漏洞结论。

## GitHub参考及应用取舍

- [OWASP REST Security](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/REST_Security_Cheat_Sheet.md)：每个非公开API独立授权，HTTPS、输入边界与错误信息控制。用于权限与接口审查基线。
- [OWASP SSRF Prevention](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.md)：地址/DNS验证和重定向控制，对照此前本地模型传输加固。
- [OWASP Secrets Management](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Secrets_Management_Cheat_Sheet.md)：密钥生命周期、最小权限及轮换。未来密钥加密需独立管理主密钥，不能把解密密钥与密文同库保存后宣称安全。
- [node-rate-limiter-flexible](https://github.com/animir/node-rate-limiter-flexible)：借鉴原子consume、共享存储和并发限制的设计。未安装；需结合现有数据库/Redis部署选型，不能拿限流替代业务配额事务。
- [javascript-obfuscator](https://github.com/javascript-obfuscator/javascript-obfuscator)：只作为前端源码阅读成本的可选层。项目README明确警告性能和体积成本，不宜全量混淆Next/React/vendor、插入debugger或把浏览器签名密钥视为秘密。本轮未安装或启用。

推荐顺序：业务额度/池配额原子预占 → IP门禁统一 → 原子共享限流 → 即时权限撤销 → 发布产物秘密/source map检查 → 评估局部混淆。请求重放应依据业务语义：一次性分析必须幂等；普通新提问不能因内容相同被永久拒绝。浏览器内持有的签名密钥无法阻止账号本人重放请求。
