# "Translate Only" 每日使用限制 — 需求文档

## 1. 背景与目标

### 1.1 背景

当前 "Translate Only" 功能（中英互译，不保存生词本）对已登录用户无使用次数限制。由于 LLM API 调用会产生费用，运营方需要在控制成本的同时，为重度用户提供使用自己 API Key 的途径。

### 1.2 目标

- 为普通（免费）用户设置每日 10 次的合理使用上限
- 超出上限后，提供友好引导，允许用户配置自己的 LLM API 继续使用
- 用户的 API Key 仅存储在本地浏览器，不上传到服务器
- 防止同一用户在同一设备上通过注册多个账号绕过次数限制

---

## 2. 预期效果（UI 交互描述）

### 2.1 正常使用 — 剩余次数提示

在 "Translate Only" 卡片中，翻译按钮下方或侧边显示剩余免费次数提示：

- 显示文案：`今日剩余免费次数：X / 10`
- 次数 > 3 时：低调灰字显示，不影响正常使用
- 次数 ≤ 3 时：暖色/橙色文字提示，提醒用户即将用尽
- 每次翻译成功完成后，剩余次数实时刷新

### 2.2 次数用尽 — 友好提示弹窗

用户当日第 10 次使用完毕后，再次点击 "开始翻译" 时：

1. **不再发起后端请求**（前端拦截）
2. 弹出模态弹窗（使用项目已有的 Radix Dialog 组件），内容布局：

```

│  10 次翻译功能。                          │
│                                         │
│  如需继续使用，可以配置您自己的大模型 API，│
│  支持 OpenAI、DeepSeek、智谱、通义千问等  │
│  兼容 OpenAI 接口的厂商。                 │
│                                         │

│  │  https://api.openai.com/v1          │ │
│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │  API Key                            │ │
```

- 弹窗标题：温馨友好，避免生硬的 "错误" 或 "拒绝" 用语
- 正文使用自然语言说明原因和解决方案
- 三个输入框：Base URL、API Key、Model
- "测试连接" 按钮：用当前输入框中的配置发送一个简短的测试请求，显示连接状态（成功/失败提示）
- "保存" 按钮：将三个字段存入 localStorage，关闭弹窗
- "取消" 按钮：关闭弹窗，不保存（下次点击翻译仍会弹出）

### 2.3 已配置自有 API — 正常使用

用户保存自有 API 配置后：

- 不再显示每日剩余次数（使用自定义 API 无限制）
- 翻译请求使用用户自有的 API 配置发送
- 在 Translate Only 卡片某处显示 "正在使用自定义 API" 标识（小标签/图标），点击可修改或清除自定义 API 配置
- 提供 "清除自定义 API 配置，切换回免费次数" 的功能入口（例如点击标签弹出确认对话框）

### 2.4 切换回免费模式

如果用户清除了自定义 API 配置：
- 恢复显示 "今日剩余免费次数：X / 10"
- 若当日 10 次已用完（从服务端查询结果），再次点击翻译仍然弹出 2.2 中的弹窗

## 3. 功能需求

### FR-1：每日免费使用次数限制

- **FR-1.1**：服务端维护每个用户每日 Translate Only 的使用计数
- **FR-1.2**：普通用户每日（UTC+8 自然日 00:00 ~ 23:59）最多 10 次免费翻译
- **FR-1.3**：管理员（`isAdmin = true`）不受此限制
- **FR-1.4**：后端 API `/api/translate-only` 在接收到翻译请求时检查用户当日使用次数，超出返回特定错误码和消息（如 `{ success: false, error: "DAILY_LIMIT_EXCEEDED", limit: 10 }`，HTTP 429）
- **FR-1.5**：使用次数仅对调用 LLM 成功返回结果的情况计数（不计入：参数校验失败、LLM 调用失败返回错误、用户使用自定义 API 的情况）
- **FR-1.6**：前端在翻译成功返回后更新本地剩余次数显示；翻译失败（如网络错误、服务端错误）不扣除次数

### FR-2：每日次数用尽提醒弹窗

- **FR-2.1**：前端在调用翻译 API 前检查本地已缓存的剩余次数，若为 0 则直接弹出提醒弹窗，不向后端发起请求
- **FR-2.2**：后端返回 `DAILY_LIMIT_EXCEEDED` 错误时，前端也应弹出相同弹窗（作为兜底逻辑，处理本地缓存与实际服务端状态不同步的情况）
- **FR-2.3**：弹窗内容包含友好提示文字、API 配置表单、测试连接和保存功能

### FR-3：自定义 LLM API 配置

- **FR-3.1**：用户可在弹窗中输入三个字段：
  - **Base URL**（API 接口地址）：默认占位符显示 `https://api.openai.com/v1`，必填
  - **API Key**：必填，使用 `type="password"` 的输入框
  - **Model**（模型名称）：默认占位符显示 `gpt-4o-mini`，必填
- **FR-3.2**：保存时对 URL 格式进行基本校验（必须以 `http://` 或 `https://` 开头）
- **FR-3.3**：三个字段以结构化对象存储于浏览器 localStorage，**不上传至服务端**
- **FR-3.4**：存储密钥与开发者在管理后台配置的 `ApiConfig`/`LlmApiProvider` 同级互不影响
- **FR-3.5**：提供 "测试连接" 功能——用用户填入的配置调用 `/v1/chat/completions` 端点，发送一条简短测试消息（如 "Hello"），根据返回结果判断连接是否成功，并在按钮旁或弹窗内展示测试结果（成功/失败 + 错误原因）

### FR-4：自定义 API 下的翻译

- **FR-4.1**：当用户已保存自定义 API 配置时，翻译请求附带自定义 API 参数（Base URL、API Key、Model），后端**直接使用用户提供的 API 信息调用 LLM**，不经过系统的 LLM Provider 池
- **FR-4.2**：使用自定义 API 的翻译不计入免费次数
- **FR-4.3**：使用自定义 API 同样需要经过身份验证、安全校验、Prompt Injection 检测等现有安全流程
- **FR-4.4**：自有 API 调用失败时，返回友好的错误提示给前端，不兜底切换为系统 API

### FR-5：自定义 API 配置标识与管理

- **FR-5.1**：Translate Only 卡片中展示 "正在使用自定义 API" 状态标识
- **FR-5.2**：用户可随时清除自定义 API 配置，恢复为免费次数模式
- **FR-5.3**：清除配置时需要二次确认（用已有的 AlertDialog 组件）

### FR-6：防止多账号绕过限制

- **FR-6.1**：前端生成设备指纹（Device ID），存储于 localStorage 中
- **FR-6.2**：每次调用 `/api/translate-only` 时，前端在请求头中携带该 Device ID（如 `X-Device-Id`）
- **FR-6.3**：后端在计数时，若请求携带 Device ID，则查询该 Device ID 在当前自然日内对应的所有用户累计使用次数，若 >= 10 次，则拒绝该请求（即使当前用户的独立次数未达上限）
- **FR-6.4**：后端建立 Device ID → 当日使用次数的映射关系，存储于数据库（新增模型或使用已有模型）
- **FR-6.5**：没有 Device ID 的请求（如通过 curl/脚本直接调用 API）仍受限于单用户每日 10 次的基本限制
- **FR-6.6**：管理员用户不参与 Device ID 关联计数（管理员不受限）

### FR-7：数据持久化

- **FR-7.1**：需新增 Prisma 模型用于持久化每日使用计数和设备指纹关联（具体模型设计见第 7 节）
- **FR-7.2**：历史数据需定期清理（如保留最近 30 天数据）

## 4. 非功能需求

### NFR-1 安全性
- 用户的 API Key 绝不离开浏览器，不在服务端日志、数据库、网络请求中出现
- API Key 发送到服务端时应仅在内存中短期存在（本次请求生命周期），不可持久化
- 自定义 API 请求同样需要经过现有的 CSRF、Prompt Injection 检测等安全防护

### NFR-2 性能
- 免费次数检查不应显著增加 API 响应延迟（目标 < 5ms），建议使用数据库索引优化查询
- Device ID 关联查询同理需保证低延迟

### NFR-3 用户体验
- 弹窗文案需温馨友好，避免引起用户反感
- 次数提示实时刷新，避免用户误解
- 测试连接反馈需在 5 秒内返回结果

### NFR-4 兼容性
- 自定义 API 需兼容所有遵循 OpenAI Chat Completions API 格式的厂商（OpenAI、DeepSeek、智谱 GLM、通义千问、Moonshot、零一万物等）
- Base URL 的路径后缀（如 `/v1`）允许用户自定义，灵活性足够

### NFR-5 向后兼容
- 已有 API 的用户行为不受影响（仍使用 10 次限制，除非配置自定义 API）
- 管理员不受任何限制

## 6. 数据模型设计建议

### 6.1 新增模型：`TranslateOnlyUsage`

```
model TranslateOnlyUsage {
  id        String   @id
  userId    String
  date      String              // yyyy-MM-dd (UTC+8)
  count     Int      @default(1)
  updatedAt DateTime @updatedAt
  User      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, date])
  @@index([date])
}
```

### 6.2 新增模型：`DeviceUsageLog`

```
model DeviceUsageLog {
  id        String   @id
  deviceId  String
  date      String              // yyyy-MM-dd (UTC+8)
  userId    String
  createdAt DateTime @default(now())

  @@index([deviceId, date])
  @@index([date])
}
```

### 6.3 现有模型修改

`UserPreference` 模型可扩展字段（不强制，也可用 localStorage）：
- `customApiBaseUrl`: String? — 用户自定义 API 地址
- `customApiKey`: String? — **注意：安全考虑，不建议将用户 API Key 存入服务端数据库，此字段仅作占位，实际存储应使用浏览器 localStorage**

> **推荐：自定义 API 配置仅存储在 localStorage 中，不在服务端数据库持久化。**

## 7. 接口设计

### 7.1 现有接口修改

**`POST /api/translate-only`** — 新增请求参数和响应错误类型

请求体新增可选字段：
```json
{
  "input": "Hello world",
  "customApi": {
    "baseUrl": "https://api.deepseek.com/v1",
    "apiKey": "sk-xxx",
    "model": "deepseek-chat"
  }
}
```

新增错误响应：
```json
{
  "success": false,
  "error": "DAILY_LIMIT_EXCEEDED",
  "message": "每日免费翻译次数已用完",
  "limit": 10
}
```
HTTP Status: `429 Too Many Requests`

### 7.2 新增接口

**`GET /api/translate-only/usage`**

获取当前用户的当日剩余免费次数：

```json
{
  "success": true,
  "data": {
    "used": 5,
    "limit": 10,
    "remaining": 5,
    "isAdmin": false
  }
}
```

### 7.3 新增接口（可选）

**`POST /api/translate-only/test-connection`**

测试用户自定义 API 连接是否有效：

请求体：
```json
{
  "baseUrl": "https://api.openai.com/v1",
  "apiKey": "sk-xxx",
  "model": "gpt-4o-mini"
}
```

响应：
```json
{
  "success": true,
  "message": "连接成功"
}
```
或
```json
{
  "success": false,
  "error": "401 Unauthorized: Invalid API Key"
}
```

## 8. 边界条件与异常处理

| 场景 | 处理方式 |
|------|----------|
| 用户未登录直接调用 API | 返回 401，不计次数 |
| 自定义 API Key 错误（401/403） | 后端返回具体错误信息给前端，不消耗免费次数 |
| 自定义 API 超时 | 设置合理超时（如 60 秒），超时返回错误 |
| 自定义 API URL 不可达 | 后端返回明确错误 "无法连接到 API 服务器"，不兜底 |
| 设备指纹被清除（localStorage 清空） | 前端生成新的 Device ID，当日可能无法再次使用翻译（因为新 Device ID 无使用记录，但旧 Device ID 已记录 10 次）——这是预期行为，不可绕过 |
| 午夜跨天 | 前端在凌晨检测日期变更，自动刷新剩余次数为 10 |
| 同一用户多设备/多浏览器 | 每个设备独立 10 次限制（不同 Device ID 不同计数），仅同设备跨账号累积计数 |
| 网络请求失败 | 不计入使用次数，不扣减本地计数 |

## 9. 约束与风险

### 9.1 约束

- 自定义 API 必须兼容 OpenAI Chat Completions 格式
- 设备指纹存储在 localStorage 中，用户可通过清除浏览器数据重置——但这同时会清除其 API Key 配置和剩余次数缓存，属于可接受的权衡
- 数据存储在 SQLite 中，需关注高并发下的写入性能

### 9.2 风险

- **风险 1**：恶意用户通过篡改请求参数绕过 Device ID 校验 → 缓解：服务端同时校验单用户次数 + Device ID 关联
- **风险 2**：localStorage 被清除导致 API Key 丢失 → 缓解：在弹窗中明确提示用户妥善保管自己的 API Key，并在输入框下方显示 "请妥善保管您的 API Key，它仅保存在本地浏览器中"
- **风险 3**：用户填入的 API 实际不可用，产生挫败感 → 缓解：提供 "测试连接" 按钮

## 10. 验收标准

- [ ] **AC-1**：普通用户每日第 1~10 次翻译正常执行，返回翻译结果
- [ ] **AC-2**：第 11 次及以后点击翻译，弹出友好提示弹窗，不发送翻译请求
- [ ] **AC-3**：弹窗中可输入 API 配置信息并保存，保存后自动关闭弹窗
- [ ] **AC-4**：弹窗中可点击 "测试连接" 验证 API 配置是否可用
- [ ] **AC-5**：使用自定义 API 翻译成功，不限次数
- [ ] **AC-6**：自定义 API 配置错误的翻译请求不影响免费次数
- [ ] **AC-7**：清除自定义 API 配置后恢复到免费次数模式
- [ ] **AC-8**：同一设备上，注册多个账号的累计翻译次数不超过 10 次/日
- [ ] **AC-9**：管理员翻译不受任何次数限制
- [ ] **AC-10**：用户的 API Key 不会出现在服务端日志、数据库或网络监控中
- [ ] **AC-11**：午夜 0:00 后自动重置免费次数
- [ ] **AC-12**：弹窗文案温馨友好，无生硬拒绝用语

## 11. 术语说明

| 术语 | 说明 |
|------|------|
| Translate Only | 项目中已存在的中英互译功能，调用 LLM 返回翻译文本，不保存到生词本 |
| Device ID | 前端生成的设备唯一标识，存储在 localStorage 中，用于跨账号关联 |
| 自定义 API | 用户自行提供的 LLM API（Base URL + API Key + Model），兼容 OpenAI 格式 |
| 免费次数 | 使用运维方提供的系统 API 进行的翻译次数，每日有 10 次限制 |
